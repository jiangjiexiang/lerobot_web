# 训练工作台接续计划

## 1. 目标

在现有 LeRobot Web 中完善独立的“训练管理”工作区，使用户能够从已审核数据出发，完成主机性能检测、训练配置、启动前检查、任务运行、指标查看、Checkpoint 管理、模型评估与受控部署。

产品规则以飞书文档为准：<https://tcnppips4y7o.feishu.cn/wiki/BuCow3dCWiAAI0kStxjcYddlncc>。

当前执行环境无法解析该飞书域名，因此本文先依据仓库现状建立接续基线。拿到可访问的文档正文后，必须先完成需求逐条映射，再继续改功能。

## 2. 当前基线

截至 `e3dc08c`，仓库已经具备以下能力，不应重复开发：

- 左侧工作区已有“训练管理”入口，包含训练实验、模型评估、模型部署三个视图。
- 训练任务可绑定 Dataset 与已发布 Collection，配置策略、设备、Batch size、Steps、Workers、Seed 和保存频率。
- 已实现 CPU、内存、磁盘、CUDA、GPU 型号、显存、GPU 利用率和温度检测。
- 已实现创建前资源估算和启动前预检，可根据显存、内存、磁盘、依赖与数据质量给出通过、警告或阻断。
- 已实现本地串行任务、日志、Loss/Grad norm 曲线、Checkpoint、停止、续训、复制、归档和 Run 对比。
- 已实现 Dataset snapshot、质量扫描、模型登记、独立评估、发布门禁、部署/回滚和运行遥测。
- 已实现 Generic SSH 云端训练 spec 导出，但不会自动连接云主机或上传数据。

## 3. 产品对齐任务

### P0：恢复飞书需求上下文

1. 获取飞书文档正文或导出的 Markdown/PDF。
2. 建立“文档条目 / 当前实现 / 差距 / 验收方式”四列表格。
3. 对不明确的训练参数、默认值、阻断规则和部署权限列出待确认项。
4. 只实现已确认差距；文档与现有行为冲突时，以文档和用户最新说明为准。

交付物：在本文追加“飞书需求映射”章节，每项标记 `已覆盖`、`部分覆盖`、`未覆盖` 或 `不采用`。

### P0：真实环境验收

1. 启动 Robot Server 与前端，确认训练入口可访问且不影响遥操作、录制和双摄像头。
2. 在目标主机核对 `nvidia-smi`、PyTorch CUDA、GPU 显存、系统内存、磁盘和温度读数。
3. 用小型已审核 Collection 创建 ACT smoke job，验证命令、状态转换、日志和输出目录。
4. 验证显存不足、磁盘不足、CUDA 不可用、数据质量失败时的阻断信息。
5. 验证停止后有 Checkpoint 时可以续训，服务重启后不会把失联进程误报为运行中。

验收标准：检测值与系统命令基本一致；阻断原因可理解；一次小训练可完整跑通且不会上传 Hugging Face/W&B。

### P1：性能检测完善

1. 将静态主机信息与实时占用分开，显示采样时间和不可用原因。
2. 增加 GPU 驱动版本、CUDA runtime、PyTorch 版本、磁盘路径、磁盘写入空间和进程占用信息。
3. 资源估算返回计算依据、建议值、实机值和安全余量，不只返回最终结论。
4. 温度、显存、内存和磁盘设置分级阈值，训练过程中持续告警但不擅自终止任务。
5. 对无 NVIDIA GPU、Jetson 统一内存和普通独显分别给出正确文案。

验收标准：每个检测项都有 `通过 / 警告 / 阻断 / 未知` 状态；未知不能被显示为通过；刷新失败保留上次值并标记过期。

### P1：训练任务可靠性

1. 把任务定义、运行状态和进程状态分离，避免单个 JSON 文件并发覆盖。
2. 记录 PID、启动时间、心跳和退出原因，服务重启后检查真实进程与输出再恢复状态。
3. 限制日志内存大小并保留磁盘日志，支持按需读取尾部内容。
4. 对任务创建、启动、停止、续训、归档和模型登记补充幂等与状态机校验。
5. 校验所有受用户输入影响的路径和命令参数，保持输出仅位于受管目录。

验收标准：重复点击不会启动两个训练；异常退出可诊断；大日志不会拖垮服务；非法状态操作返回明确的 `4xx`。

### P1：训练体验补齐

1. 用策略模板提供推荐参数，并允许从已有 Run 克隆后修改。
2. 任务列表增加状态、策略、Dataset、创建时间筛选与排序。
3. 指标图支持时间范围、悬浮值、Loss 平滑和多个 Run 的一致坐标轴。
4. Checkpoint 显示最佳/最新标识、指标摘要、完整性状态和登记来源。
5. 长任务操作增加确认、进行中、成功、失败和空状态，移动端不出现文字溢出或按钮重叠。

验收标准：新用户能在一个页面完成“选数据 → 配参数 → 看预检 → 启动 → 看结果”，危险操作均有明确反馈。

## 4. 竞品借鉴边界

优先借鉴成熟交互和信息组织，不复制品牌视觉、专有文案或闭源实现。

| 平台 | 借鉴内容 | 本项目落点 |
| --- | --- | --- |
| Weights & Biases | Run 表格、配置与指标并列、Run 对比 | 任务列表、详情与多 Run 曲线 |
| MLflow | Experiment / Run 层级、参数指标产物统一追踪 | Dataset/Collection、任务、Checkpoint 关联 |
| ClearML | Queue、Agent、Clone/Continue、资源监控 | 本地队列、后续远端 Agent、复制与续训 |
| NVIDIA Base Command | 资源规格、作业状态、产物和日志 | 主机能力门禁与任务详情 |
| Hugging Face AutoTrain | 向导式创建、推荐默认值、错误提示 | 策略模板和低门槛任务表单 |
| Roboto / Foxglove / FiftyOne | 数据版本、质量、审核和可追溯性 | Collection snapshot 与训练数据血缘 |

竞品调研必须记录公开链接、截图日期和可借鉴结论；没有证据的能力不写成事实。

## 5. 建议实施顺序

1. **需求对齐**：导入飞书正文，完成需求矩阵并冻结 P0 范围。
2. **基线验证**：构建前后端，在真实主机执行性能检测和 ACT smoke job。
3. **修复阻断**：先处理数据安全、进程状态、资源误判和训练无法完成的问题。
4. **体验完善**：补筛选、模板、指标图和操作反馈。
5. **回归验收**：覆盖控制、录制、数据、训练、评估与部署的关键路径。
6. **文档收口**：更新 README、API 清单、运维说明和已知限制。

- 使用 demo Dataset 跑通创建、预检、启动、停止、续训、完成、Checkpoint 校验和模型登记。

## 7. 完成定义

满足以下条件后，训练工作台才算“完善起来”：

- 飞书需求均有明确映射，没有未说明的遗漏。
- 目标主机性能检测真实、可解释，错误条件不会误放行训练。
- 至少一个 ACT 小任务在目标机器端到端完成，并产生可校验 Checkpoint。
- 任务停止、失败、续训和服务重启场景经过验证。
- 训练新增功能不破坏遥操作、数据录制、数据审核和摄像头视频流。
- 前后端构建通过，关键接口和人工验收结果记录在文档中。

## 9. 验收记录（2026-07-27）

### 已通过

- `frontend` 与 `robot-server` 均通过 TypeScript/生产构建。
- 使用正式 LeRobot Python 环境和 `ENABLE_CAMERA=0` 在独立端口启动 Robot Server，健康检查与构建后静态页面均返回 `200`。
- 主机检测可返回 CPU、内存、磁盘和 Orin 统一内存 GPU 信息；CPU 训练不作为本项目验收范围。
- 实时资源接口返回 CPU、内存、磁盘、GPU load、温度和采样时间。
- Dataset 与 Collection 可读取；`demo_pick_place/v001` 仅包含审核通过的 Episode 0。
- Dataset 质量扫描覆盖 3 个 Episode，视频可读、轨迹有限且未发现黑屏、冻结、突变或重复风险。
- 资源估算可按设备与策略返回容量结论，非法策略和 Batch size 返回 `400`；正式验收以目标 CUDA 环境为准。
- 草稿训练任务预检覆盖数据、质量、LeRobot/PyTorch、设备、磁盘、内存、资源估算和设备独占，所有检查均返回结构化结果。
- 已有 `smoke_act_1step` ACT 任务真实完成 1 step，退出码为 0，记录 Loss/Grad norm/LR，并生成 Checkpoint。
- Checkpoint `model.safetensors` 的 SHA-256 与模型登记记录一致。
- Generic SSH 云端 spec、Dataset snapshot、模型评估统计、Wilson 区间、发布门禁、部署修订、运行遥测和异常闭环均可读取。
- 状态机拒绝分支正常：重复启动已完成任务返回 `409`，不存在任务返回 `404`。

### 验收修复

- 修复训练预检把“已用内存”误标为“可用内存”的错误。修复前预检显示约 4.0 GB，修复后主机检测与预检一致显示约 11.4 GB，避免内存门禁误判。
- 修复摄像头响应式布局：画面容器从错误的 4:3 改为与 `640x360` 视频一致的 16:9，移除在窄屏撑开布局的固定最小高度，并按摄像头区域实际宽度自动切换单列或双列。
- 训练工作台采用“任务列表 + 详情面板”结构：新建配置按需展开，队列支持搜索与状态筛选，任务详情拆为概览、指标、产物与日志，避免配置表单长期挤压高频监控区域。

设计依据来自公开文档：W&B Workspace 支持搜索、工作区视图和交互式 Run 可视化；MLflow Tracking 围绕 Run 组织参数、指标与产物；ClearML 同时提供任务表信息面板和全屏详情，并将标量、产物与控制台分区展示。
